# C 語言基礎學習筆記

記錄學習 C 語言過程中，一些容易搞混、值得記下來的基礎知識點。

## 1. 為何不同位元系統下，`int` 的大小不一樣？

`int` 的大小不是 C 語言規格寫死的固定值，而是**編譯器為了對齊 CPU 暫存器（register）自然寬度**所做的實作慣例：CPU 一次能處理多少 bits，`int` 就傾向對齊那個寬度，這樣運算效率最高。

| 系統位元數 | int 資料長度 | 最小值 | 最大值 | 為何定義這個長度 |
|---|---|---|---|---|
| 16位元 | 2 bytes (16 bits) | -32,768 | 32,767 | CPU 通用暫存器是 16-bit 寬，`int` 對齊暫存器寬度，一個指令即可完成運算，效率最高 |
| 32位元 | 4 bytes (32 bits) | -2,147,483,648 | 2,147,483,647 | CPU 暫存器升級為 32-bit，`int` 跟著放大到對齊新的暫存器寬度，避免浪費硬體算力、也符合當時程式對數值範圍的需求 |
| 64位元 | 4 bytes (32 bits，維持不變) | -2,147,483,648 | 2,147,483,647 | 暫存器已是 64-bit，但 `int` **刻意不跟著放大**，以維持與大量既有 32-bit 程式碼、檔案格式、API 的相容性；擴充到 64-bit 範圍的需求改由 `long`／`long long`／指標承擔 |

**核心結論：** 16→32 位元時代 `int` 隨硬體變大，但到了 64 位元時代，相容性考量勝過「跟硬體對齊」，所以 `int` 就此凍結在 4 bytes，不再繼續放大。這也是為什麼 Windows（LLP64）和 Linux/macOS（LP64）在 64 位元下 `int` 都維持 4 bytes，差異只出現在 `long` 的大小上（詳見 [README_tech.md](README_tech.md) 的 32/64 位元編譯器差異說明）。

## 2. 浮點數精度如何避免誤差？

C 有三種浮點型別，精度由 IEEE 754 標準決定：

| 型別 | 大小 | 有效位數（十進位） | 範圍 |
|---|---|---|---|
| `float`（單精度） | 4 bytes | 約 6~7 位 | ±3.4 × 10³⁸ |
| `double`（倍精度） | 8 bytes | 約 15~16 位 | ±1.7 × 10³⁰⁸ |
| `long double` | 8~16 bytes（平台相關） | 視編譯器而定（MinGW/GCC 常見 80-bit 擴展精度，MSVC 常等同 double） | 更大 |

浮點數的不精確有好幾種不同成因，對策也不一樣，不能一概用「換更大的型別」解決：

| 應避免的問題 | 對策 |
|---|---|
| 十進位小數轉二進位失真（例如 0.1 存不精確） | 改用整數（分/最小單位）運算，不要用浮點數，例如金額以「分」為單位存成 `int` |
| 有效位數不夠（`float` 只有 ~6~7 位） | `float` → `double`（優先），必要時 `long double` |
| 運算誤差累積（大量連續加總、大數相減） | 減少運算次數、用 Kahan summation（補償求和演算法）、避免「大數 - 相近大數」(catastrophic cancellation) |
| 誤用 `==` 比較浮點數是否相等 | 用 `fabs(a - b) < epsilon` 判斷誤差範圍，不要用 `==` |
| 需要極高/任意精度（科學計算等級） | 用 GMP、MPFR 等任意精度數學函式庫，內建浮點型別無法滿足 |

**核心結論：** `float`/`double` 對十進位小數的誤差是二進位表示法的本質限制，換型別解決不了；真正需要精確十進位（如金額）時，正確做法是**用整數運算避開浮點數**，而不是硬用更高精度的浮點型別。

## 3. 命令列互動：`main(int argc, char *argv[])`

若想在**執行時**接收使用者從命令列傳進來的參數（例如 `test_a.exe hello world`），要靠 `main` 的兩個參數，而不是 `scanf`：

```c
int main(int argc, char *argv[]) // 標準 C 只有 int main(void) 和這一款
{
    int i;
    if (argc == 1)
    {
        printf("無引數傳入\n");
    }
    else
    {
        printf("引數有\n");
        for (i = 0; i < argc; i++)
        {
            puts(argv[i]);
        }
    }
    return 0;
}
```

| 參數 | 型別 | 意義 |
|---|---|---|
| `argc` | `int` | argument count，命令列引數的**個數**，永遠 ≥ 1 |
| `argv` | `char *argv[]`、`char **argv` | argument vector，每個元素是一個字串指標，指向對應的引數內容 |

- `argv[0]` 永遠是「程式本身的路徑/名稱」，真正的第一個引數是 `argv[1]`。
- `argc` 因為把 `argv[0]` 也算進去，所以「沒有額外引數」時 `argc == 1`。
- `argv` 陣列最後一個元素之後，保證有一個 `NULL`（即 `argv[argc] == NULL`），可以用來當作陣列結尾判斷，不一定要依賴 `argc`。
- 命令列上的每個引數都是**字串**（`char *`），輸入是數字，也不會自動變成 `int`。

**執行範例（在終端機輸入）：**
```
> test_a.exe foo bar
引數有
test_a.exe
foo
bar
```

> **核心結論：** 想讓程式在**啟動當下**就拿到外部輸入（不是執行中才問使用者），就是靠 `main` 的 `argc`／`argv`；`argc` 告訴你有幾個引數（含程式自己），`argv` 是字串指標陣列，`argv[0]` 是程式名稱、`argv[1]` 起才是真正的使用者輸入，且每個引數都要自己視需要轉型。

## 4. 常用資料型別與進位制的表示法

- 進位制

| 資料型別 | 顯示(原始碼字面) | 10 進制 | 16 進制 | 8 進制 | 2 進制 |
| -- | -- | -- | -- | -- | -- |
| int | `80` | 80 | `0x50` | `0120` | `01010000` |
| char | `'A'` | 65 | `0x41` 或 `'\x41'` | `0101` 或 `'\101'` | `01000001` |

> 注意：整數常數字面值加前綴 `0` 代表八進位（如 `0120`），加 `0x` 代表十六進位（如 `0x50`）；`char` 的跳脫序列則寫成 `\101`（八進位，不加前綴 0）或 `\x41`（十六進位），語法跟一般整數常數不同。

- printf 與 scanf 的格式化設定 (在 <stdio.h> 標頭檔)
    - `%d`：帶正負號的十進位整數(int)
    - `%6d`：帶正負號的十進位整數(int)，且總欄位寬度是6字元
    - `%x` / `%X`：十六進位（小寫/大寫）
    - `%o`：八進位
    - `%c`：把整數值當成 ASCII 碼，印成對應字元
    - `%f`：浮點數 (注意精度)
    - `%8.2f`：浮點數 (注意精度)，且總欄位寬度是8字元，小數位2字元
    - `%e`：科學記號
    - `%s`：字串，以空白、Tab、Enter斷開前一個%s
    - `%3s`：字串，限定3碼
    - `%p`：指標
    - `%%`：印出字面上的 `%` 符號

## 5. 允許省略的寫法

- **多維陣列初始化，允許「第一維」的長度不寫**（其餘維度必須明確指定）：
  ```c
  int arr[][3] = {{1, 2, 3}, {4, 5, 6}};
  // 編譯器會依初始化內容自動推算第一維長度為 2，等同於 int arr[2][3] = {...};
  ```
  > 只有**第一維**可以省略；第二維以後一定要寫，編譯器才能算出每一列佔多少記憶體、正確切割初始化內容。

- **`for` 迴圈的初始值、條件式、遞增/遞減，三個欄位都可以留白**（但分號 `;` 不能省略）：
  ```c
  for (;;) {
      // 條件式留白視為「恆為真」，等同 while (1)，變成無窮迴圈
      // 需搭配 break 才能跳出
  }

  int i = 0;
  for (; i < 3; i++) {
      // 初始值留白：因為 i 已經在迴圈外先宣告、賦值過了
  }
  ```

## 6. 字串的賦值

C 沒有內建的「字串型別」，字串常數的賦值方式，依存放的容器不同，行為差很多：

- **字元陣列（`char[]`）：字串存放在自己的記憶體裡，是一份可修改的複本**
  ```c
  char s1[] = "Hi";
  // 初始化時可以用字串常數賦值，長度可省略、自動推算（含結尾的 '\0'）
  // 等同 char s1[3] = {'H', 'i', '\0'};  sizeof(s1) 是 3，不是 2（多算結尾的 '\0'）

  char s2[10];
  strcpy(s2, "Hello");   // 「宣告完之後」不能再整個用 = 賦值，只能靠 strcpy 之類的函式逐一複製內容
  // s2 = "Hello";       // 錯誤：編譯失敗，陣列名稱不是「可修改的左值」，不能直接賦值
  s2[0] = 'h';           // 合法：陣列存的是一份可寫入的複本，可以逐字元修改內容
  ```

- **字元指標（`char *`）：指向字串常數，指標可以重新指向、但內容本身唯讀**
  ```c
  char *s3 = "World";
  s3 = "Changed";   // 合法：只是讓指標改指向另一個字串常數的位址
  // s3[0] = 'w';   // 編譯不會報錯，但執行時是未定義行為（企圖修改唯讀記憶體，常會 crash）
  ```

> **核心結論：** `char[]` 是「裝字串的容器」，等於複製一份**可修改**的字串資料，內容可改但整體不能重新賦值，適合需要修改內容的情境；`char *` 是「指向字串的指標」，指向的是一份**唯讀**的字串常量，指標本身可以重新指向別的字串、但常數內容不可修改，適合只需要讀取、或需要靈活切換指向不同字串的情境。

## 7. 為什麼 `printf` 用 `%p` 時要加 `(void*)`？

這是 C 語言標準的規定！`%p` 這個格式化符號，規格上**只接受 `void*` 型別的參數**。

```c
int x = 10;
int *p = &x;

printf("%p\n", p);           // 未定義行為：p 是 int*，型別跟 %p 要求的 void* 不符
printf("%p\n", (void*)p);    // 正確：明確轉型成 void*，符合規格
```

- 不同型別的指標（`int*`、`char*`、`double*` …）在某些平台上大小或表示法可能不同，編譯器/標準並不保證直接把它們當 `void*` 傳給 `printf` 也能正常運作。
- 加上 `(void*)` 轉型，等於明確告訴編譯器「照 `void*` 的規格來傳這個參數」，才是符合標準、可移植的寫法。
- 忘記轉型多數情況下看起來也會印出正確的位址，但這是**未定義行為**、不保證在所有編譯器與平台上都正確，寫法上仍應養成習慣加上 `(void*)`。

> **核心結論：** `%p` 只認 `void*`；傳入其他指標型別前，一律先用 `(void*)` 轉型，這不是多此一舉，而是符合 C 標準的正確用法。

## 8. 二維陣列的位址計算：編譯器需要知道「每一列有多大」

`arr` 的型別是 `int (*)[4]`，也就是「指向『4 個 int』區塊的指標」——每次對 `arr` 做指標運算（`arr + i`），一次跳的單位是「一整列 4 個 int」，而不是「一個 int」。故寫 `arr[i][j]`，編譯器實際上做的事，是把它展開成指標運算：

```c
// 語法糖
arr[i][j]
// 等同於位址計算公式
*(*(arr + i) + j)

// 起始位址 + i × (每列大小) + j × (每個元素大小)
// 起始位址 + i × (4 × sizeof(int)) + j × sizeof(int) 
```

- `no + i`：跳過 i 列，每列大小是 `4 × sizeof(int)`，算出第 i 列的起始位址。
- `*(no + i) + j`：在第 i 列裡，再跳過 j 個 int，算出 `no[i][j]` 的位址。
- 最外層的 `*`：對這個位址取值，拿到 `no[i][j]` 真正存的整數。

## 9. 哪些情況需要釋放指標 `free()`？

C 語言的記憶體分成兩種來源，只有其中一種需要自己手動釋放：

- **凡是用 `malloc` / `calloc` / `realloc` 配置出來的 → 一定要 `free()`：**
  ```c
  #include <stdlib.h>   // malloc / free 宣告在這個標頭檔
  // 動態配置：向系統要一塊記憶體（配置在 heap）
  // 一般 int 變數
  int *p1 = malloc(1 * sizeof(int));
  // 一維陣列 int 變數
  int *p2 = malloc(10 * sizeof(int));
  // 字串
  char *p3 = malloc(10 * sizeof(char));
  // 二維陣列（字串陣列）：p4 是「指標的指標」，先配置指標陣列本身，再各自配置每個字串
  int n = 3;
  char **p4 = malloc(n * sizeof(char *));
  for (int i = 0; i < n; i++) {
      // p4[i] 是賦值給已存在的陣列元素，不是重新宣告
      p4[i] = malloc(10 * sizeof(char));   
  }

  // ... 使用 p1、p2、p3、p4 ...

  // free() 一次只能釋放一個指標，逐一呼叫
  // p4 要先釋放內層、再釋放外層，否則內層會 memory leak
  free(p1);
  free(p2);
  free(p3);
  for (int i = 0; i < n; i++) {
      free(p4[i]);
  }
  free(p4);

  // 好習慣：釋放後把指標設為 NULL
  p1 = NULL;
  p2 = NULL;
  p3 = NULL;
  p4 = NULL;
  ```
  這類記憶體是**手動配置、手動歸還**，程式結束前若忘記 `free()`，這塊記憶體在程式執行期間就一直被佔用、拿不回來，直到程式結束才會被作業系統整個回收。

- **凡是宣告時直接寫死大小的區域變數 / 陣列 / 全域變數 → 不需要、也不能 `free()`：**
  ```c
  int x = 10;          // 區域變數，配置在 stack，函式結束自動釋放
  int arr[5];          // 陣列，配置在 stack（或全域區），生命週期結束自動釋放
  // free(&x);         // 錯誤：這不是 malloc 配置出來的記憶體，free() 會導致未定義行為，常會 crash
  ```
  這類記憶體是**編譯器自動管理**，大小在編譯期就固定，離開作用域（區域變數）或程式結束（全域變數）時自動釋放，開發者不用也不能插手。

> **注意：** `free()` 之後別忘了「不要重複釋放（double free）」——同一塊記憶體 `free()` 兩次是未定義行為，常導致 crash 或資料毀損；好習慣是釋放後把指標設為 `NULL`，因為 `free(NULL)` 是安全、合法的操作（什麼都不做），可以避免因為誤用「懸空指標（dangling pointer，指向已釋放記憶體的指標）」而造成的錯誤。

> **核心結論：** 記憶體「誰配置、誰負責釋放」——`malloc`/`calloc`/`realloc` 系列是跟系統要來的 heap 記憶體，用完要自己 `free()`；區域變數、陣列、全域變數是編譯器自動管理的 stack/靜態記憶體，生命週期到了會自動釋放，完全不需要（也不能）手動 `free()`。

## 10. Call by address（傳址呼叫）

想讓函式**真的改到呼叫端的變數**，就要用 **call by address（傳址）**：不是傳變數的值，而是傳變數的**位址**（指標）。

```c
void add_one(int *n)      // 參數，是接收 x 數值
{
    *n += 1;
}

int main(void)
{
    int x = 5;
    add_one(&x);          // 引數，是傳入 x 位址
    printf("%d\n", x);
}
```

- `add_one(int *n)`：參數 `n` 是**指標**，存的是呼叫端變數的位址；`*n` 表示「透過這個位址去存取/修改原本的變數」。
- 呼叫時要用 `&x` 把 `x` 的位址傳進去，而不是直接傳 `x`；函式內要用 `*n` 取值/寫入，而不是直接用 `n`（`n` 本身只是位址，`*n` 才是位址指向的內容）。

**常見使用情境**

| 案例 | 為什麼需要 call by address |
|---|---|
| 1. 函式想回傳一個以上結果 | C 的 `return` 只能回傳一個值，要修改多個呼叫端變數，只能靠傳位址 |
| 2. 函式要修改呼叫端變數 | `scanf("%d", &num)` 要把讀到的值寫回呼叫端的 `num`，所以一定要傳位址 |
| 3. 避免複製大型資料（陣列、結構） | 傳址只複製一個指標（4/8 bytes），不用整份複製，效率更高 |

## 11. `extern`：跨檔案共用變數、以及向前引用變數

> 用 `extern` 解決的是編譯器/連結器怎麼知道某個變數存在的問題，本身不建立新的記憶體，先讓編譯器知道型別和名字，真正的記憶體配置留給唯一的那份定義負責。

C 的全域變數有「定義 definition」、「宣告 declaration」之分：定義會真的配置記憶體、整個程式只能有一份；`extern` 是宣告，告訴編譯器「這個名字在別的地方存在，型別是這樣」，不配置記憶體、可以重複出現。

- **跨檔案共用同一個全域變數**：多個 `.c` 檔想共用同一個變數時，不能每個檔案都各自定義一份（連結階段會報 `multiple definition` 錯誤）。做法是只在一個檔案定義，其他檔案用 `extern` 宣告，連結時再由 linker 接回同一份記憶體。
- **同一檔案內引用「後面才定義」的變數**：C 是由上往下編譯，用到某個名字前編譯器必須先看過宣告。若變數定義寫在使用處後面，可以先用 `extern` 補一個宣告，讓編譯器提前知道型別，之後才看到真正的定義。

> **注意：** `extern` 宣告若同時給初始值，會被當成定義而非單純宣告，失去「不佔記憶體、可重複出現」的意義，宣告與定義要分開寫。
